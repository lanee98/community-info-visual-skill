# community-info-visual-skill

社区公共信息主视觉设计 Skill —— 把一批社区公众信息，组织成居民能快速识别、且关键信息零误差的海报主视觉。

> 课程作业 · 人工智能与设计创新 ｜ version 2.5.0

## 这个 Skill 解决什么

社区/机构手上往往已经有一批公众信息（防护提示、服务告知、导视指引、应急通知、办事指引……），缺的不是数据，而是**把它们组织成一张居民愿意看、看得懂、不会看错的海报**。

本 Skill 的核心是**换题不换流程**：不管题面是高温、严寒、停电、接种还是办事指引，底层命题不变 ——

> 把一批社区公众信息，组织成居民能快速识别、且关键信息零误差的主视觉海报。

所以它不围绕任何单一主题写死，而是给出一条**按「信息调性」定强度**的生产线。开工第一件事是判断题目的调性，再决定视觉强度与层级重心。

| 调性 | 传播目标 | 识别指标 |
| --- | --- | --- |
| **应急警示型** | 让居民立刻做对事、不白跑 | 3 秒看懂是什么 / 10 秒拿到行动 / 30 秒找到详情 |
| **服务告知型** | 让居民知道去哪、怎么办 | 3 秒知道是什么事 / 10 秒找到时间地点 / 30 秒找到电话与流程 |

## 工作流程

```
0 题目判定 ─→ 1 需求分析与输入清点 ─→ 2 资料组织·筛选·分级
                                            │
                                    ▲ 确认门 ①：事实核对单
                                            ▼
3 方案构思 ─────────────────────────→ 4 生成与制作（分层生产）
   ▲ 确认门 ②：版面方案（2–3 个选项）
                                            ▼
                              5 评价与验收（逐项通过）
                                            │
                                    ▲ 确认门 ③：成图验收（人眼看成品）
                                            ▼
                                        6 迭代与交付
```

**三道人工确认门是硬性卡点，不可跳过**：

- **确认门 ①（事实核对）** —— 进入方案构思前，把电话、机构名称、地址、时间、数量等全部锁定信息整理成事实核对单，用户确认后才继续。
- **确认门 ②（版面方案）** —— 动手生成前，给 2–3 个版式选项并说明取舍，用户选定后才开始画图。
- **确认门 ③（成图验收）** —— 出图后，把中英成图 + 两栏验收记录（测量项 / 语义项）+ 交付说明一并呈交，用户明确通过后才交付。**这是全流程唯一"人眼看成品"的机会**——"机器全绿"不等于"用户满意"。

存在的意义：把"方向错了重来"的成本，提前换成"确认一次"的成本；把"机器全绿但用户不满意"的风险拦在交付之前。

> **用户裁定优先**：三道门处，用户对字号、占比、配色、风格、骨架的明确裁定优先于 skill 默认值与区间带；留"用户覆盖 + 覆盖值 + 原默认值"三要素。**不可覆盖线**：信息零误差、对比度下限、最小字号（15px）、母本逐字。

**执行环境三档**（按能力选路线，不是按喜好）：

| 档位 | 环境 | 图形产出路线 |
| --- | --- | --- |
| 全功能 | 本地工具链 + 生图可用 | AI 生图（图生图）→ 后制排版 → 渲染导出 |
| 半功能 | 无生图、可本地渲染 | SVG / CSS 代码绘制主视觉，或合成用户素材（留痕） |
| 纯对话 | 网页版（无生图、无本地执行） | 出 HTML + 成图文字清单；渲染/断言脚本由用户本地执行 |

## 三条底线

1. **信息零误差，事实零编造** —— 时间、地点、电话、名称、流程步骤与母本逐字一致。母本里没有的，一律列入事实核对单，确认前用 `【待确认】` 占位，**不许用"看起来合理"的示例值顶替**。
2. **识别有指标** —— 主标题与关键信息必须能远观辨认，按调性走对应的 3 / 10 / 30 秒测试。
3. **受众适配** —— 以"看得清"为底线：对比度与最小字号**永不豁免**，正文受用字与排版禁令约束。

## 目录结构

```
community-info-visual-skill/
├─ SKILL.md                          主流程（中文）：调性判定 / 6 步流水线 / 三道确认门 / 三条底线
├─ SKILL_EN.md                       English version of the same pipeline
└─ references/                       按需加载的参考文件
   ├─ information-accuracy.md        信息准确性与母本核对（含确认门 ①、PDF 母本提取规程）
   ├─ information-filtering.md       信息筛选与密度分级（D 级判定、超量取舍、行动条目数量规则）
   ├─ layout-composition.md          排版与可读性规范（画布基准/字号百分比带/栅格/图标/对比度/用字禁令/字体链/双语/10 种骨架/插画规程）
   ├─ production-spec.md             生产规范（渲染器/导出链/交互截图禁令/字体守卫/稳定性断言）
   └─ visual-style-library.md        视觉风格库（S1–S11 风格 + 组合建议）
```

`SKILL.md` 只写流程与硬条款，体量大的规则（版式骨架库、风格库、插画规程、生产规范）拆进 `references/` 按需加载 —— 这样主文件保持可读，细节又能查。

## 怎么用

把整个文件夹放进 skills 目录即可：

```bash
# 用户级（对所有项目生效）
mv community-info-visual-skill ~/.workbuddy/skills/
```

然后对 AI 说"帮我把这批社区信息做成一张海报"，Skill 会按上面的流程走，并在三道确认门前停下来等你拍板。
